# Обзор API MAX

Источник: документация MAX API [3].

## Базовый домен

Основной домен платформенного API MAX: `https://platform-api2.max.ru`.

Запросы к API выполняются по HTTPS. Для работы бота используются JSON-запросы и JSON-ответы. Клиент должен явно обрабатывать сетевые ошибки, лимиты и неуспешные HTTP-статусы.

## Авторизация

Авторизация выполняется через HTTP-заголовок:

```http
Authorization: <token>
```

В production-коде токен берется из переменной окружения и не передается через query-параметры. Для MaxIDBot токен хранится в `.env` как `BOT_TOKEN` и загружается через `config.py`.

## HTTP-методы

MAX API использует стандартные HTTP-методы:

- `GET` — получение объектов и списков.
- `POST` — создание сообщений, загрузка файлов, выполнение действий бота.
- `PUT` — полное обновление ресурса или сообщения, если метод поддерживается.
- `PATCH` — частичное обновление ресурса, например настроек чата.
- `DELETE` — удаление ресурса или отвязка бота от сущности.

## Коды ответов

- `200` — запрос выполнен успешно.
- `400` — некорректный запрос или параметры.
- `401` — ошибка авторизации, токен отсутствует или неверен.
- `404` — объект не найден.
- `405` — метод не поддерживается для указанного ресурса.
- `429` — превышен лимит запросов.
- `503` — сервис временно недоступен.

Для проверки подписки важно считать timeout, `403`, `5xx` и сетевые ошибки временной проблемой API, а не виной пользователя.

## Лимиты

Ограничение API: до 30 запросов в секунду. Для операций, которые могут вызываться часто, нужен кэш или другая защита от лишних запросов.

В MaxIDBot проверка подписки должна кэшироваться на 5 минут на пользователя, чтобы не дергать `GET /chats/{chatId}/members` при каждом клике.

## Production-режим

Для production рекомендуется Webhook. Long polling допустим для разработки и отладки, но в боевом режиме бот должен принимать события через Webhook.
