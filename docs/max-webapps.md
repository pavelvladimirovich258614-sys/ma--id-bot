# Мини-приложения и Web Apps MAX

Источник: документация MAX Web Apps [2].

## Общая модель

Мини-приложения MAX — это веб-приложения на HTML, JavaScript и CSS, которые запускаются внутри клиента MAX. Они могут использовать данные запуска, диплинки и интеграцию с клиентом через MAX Bridge.

## Требования к URL

URL мини-приложения должен соответствовать требованиям:

- использовать HTTPS;
- быть доступным из клиента MAX;
- иметь длину не более 1024 символов.

Для production-сценариев нужно использовать стабильный публичный HTTPS-домен.

## Диплинки

Мини-приложение можно открыть через диплинк:

```text
https://max.ru/<botName>?startapp=<payload>
```

`payload` передает стартовые данные в приложение. Ограничение: до 512 символов. Допустимые символы: `A-Z`, `a-z`, `0-9`, `_`, `-`.

Диплинки подходят для передачи короткого контекста запуска, но не должны использоваться для секретов.

## Шеринг контента

Для публикации контента из мини-приложения используется `shareMaxContent()`. Метод позволяет инициировать сценарий шаринга в клиенте MAX и передать пользователю подготовленный контент.

## MAX Bridge

MAX Bridge — слой связи между Web App и клиентом MAX. Через него мини-приложение может обращаться к возможностям контейнера, получать параметры запуска и запускать клиентские действия.

Для MaxIDBot Web Apps не являются основной частью текущей архитектуры, но правила диплинков полезны при развитии канала, кнопок и промо-сценариев.
