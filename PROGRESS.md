## Актуальный состав проекта

- Runtime бота: `max-id-bot.service`.
- Админ-панель: FastAPI + PostgreSQL + Redis.
- Фоновая очередь: Celery только для рассылок, очередь `broadcasts`.
- MAX ID-функции: ID пользователя, бота, чата, канала, стикера.
- ID-Harvester: ID по ссылке, ID по пересланному сообщению, ID текущего бота.
- Аналитика найденных ID: таблица `discovered_entities` и раздел админки «Найденные объекты».

## Verified State 2026-05-22

- Polling-бот инициализирует `maxapi` Bot/Dispatcher, SQLite users storage и регистрирует обработчики start, callbacks, messages, bot_added и subscription events.
- Базовые MAX ID-сценарии реализованы через SDK-вызовы обработчиков: кнопки пользователя, бота, чата, канала, данные стикера, поиск по MAX-ссылке и пересланному сообщению.
- Проверка доступа вынесена в `require_subscription`: первый защищенный запрос бесплатный, далее используется кэш SQLite, события подписки и members API MAX.
- Состояние пользователей подписки хранится локально в SQLite и синхронизируется с PostgreSQL админ-панели.
- Админ-панель уже содержит авторизацию владельца, dashboard, таблицу пользователей, найденные ID, логи и запуск рассылок.
- Рассылки выполняются Celery-задачами через прямые HTTP-запросы к MAX API и пишут прогресс в PostgreSQL.
- Автоматических тестов в проекте не обнаружено; этот verified state подтвержден чтением кода и текущих harness-файлов, без запуска функционального кода.
